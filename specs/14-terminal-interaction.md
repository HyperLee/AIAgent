## 2. 目前基線、模組責任與內部介面

目前 `ChatInputReader` 是有界隱藏單行讀取器；Enter 提交、兩種刪除鍵都刪尾端 scalar、導覽鍵忽略，沒有輸入歷史。`ConsoleChatInteraction` 的一般輸入、認證選單及三種核准共用其讀取／CRLF 處理；隱藏 Key 亦共用按鍵取得。不能直接把共用 `Read` 改成多行，否則會一併改變核准與 Key 的操作。

| 元件 | 後續責任 |
|---|---|
| `ChatApplication` | 單行指令閘門、一般訊息准入後通知歷史收錄、共同清除／認證交接；仍擁有回合、授權、Context、規則、證據及用量。 |
| `ConsoleChatInteraction`／一般編輯器 | 擁有草稿、游標、貼上子狀態、預覽與有界輸入歷史；一般編輯器獨立於舊隱藏單行讀取路徑。 |

## 3. 一般訊息編輯與 Unicode

| 按鍵 | 一般編輯時的定案行為 |
|---|---|
| Enter／CR／LF | 提交目前草稿；CRLF 視為一次 Enter。Ctrl＋J／Ctrl＋Enter 若被終端機映射成 LF，亦按 Enter，不另設別名。 |
| F2 | 請求第 5 節的完整安全預覽，不提交。 |
| F3 | 進入第 4 節的貼上收集。 |
| F4 | 在游標插入一個 LF。 |
| Left／Right | 移動一個文字元素，LF 亦可跨越；不把 Tab 展開成空白。 |
| Home／End | 移到目前邏輯行的開頭／結尾，不跨過該行 LF。 |
| Up／Down | 移到上一／下一邏輯行相同文字元素欄；較短時夾至該行結尾，沒有相鄰行時無動作。 |
| Backspace／Delete | 刪除游標前／後一個文字元素；邊界無動作；刪除 LF 會合併兩行。 |
| Ctrl＋P／Ctrl＋N | 第 6 節的上一／下一筆歷史。 |
| Ctrl＋U | 清空草稿並回到起點；不移除該次輸入的無效旗標。 |
| Tab | 插入字面 U+0009；不是補全、焦點切換或自動縮排。 |
| Ctrl＋C／Ctrl＋D／EOF | 依目前 Core 狀態取消／停止；不當成文字或只清空草稿。 |

| 編號 | 要求 |
|---|---|

## 4. 明確貼上收集

使用者操作為：F3 → 等待固定收集提示 → 使用終端機原有貼上功能 → 等待貼上完成 → F3 → 等待回到編輯提示 → 可選 F2 → 另按 Enter 送出。程式不主動讀剪貼簿。

| 編號 | 要求 |
|---|---|
| TERM-025 | 進入收集時保留目前草稿及游標，不另開緩衝或讀取者；顯示「貼上收集中；換行不送出，F3 結束收集。」完成提示後排空當時已緩衝的普通輸入，再接受收集內容。使用者須在提示後開始貼上，過早內容可丟棄。 |
| TERM-026 | 收集內容在當前游標依序插入；CRLF／單獨 CR／單獨 LF 各正規化為一個 LF，Tab 與一般 Unicode 保留，總量仍受同一 16384 上限。Enter 只是內容 LF，不提交、不解析命令；貼上結尾換行亦保留。 |
| TERM-027 | 收集中只有 F3 結束、Ctrl＋C／D／EOF 停止，以及文字／Tab／換行收錄。Backspace、Delete、導覽、F2、F4、Ctrl＋P／N／U 及其他非文字鍵均不是編輯或預覽操作，而使本次輸入無效；字元不執行為指令。 |
| TERM-028 | 結束收集顯示「貼上收集已結束；尚未送出，F2 預覽或 Enter 送出。」；輸出後排空已緩衝普通輸入，再啟用正常編輯。該 F3、殘餘 CRLF 或排空時的 Enter 不能同時提交；排空仍處理取消／EOF／I/O 失敗。 |
| TERM-029 | 無效收集仍消耗輸入，直到 F3 結束或停止，不因超限／非法字元自動切回編輯。結束後的下一次 Enter 整筆 Invalid，不將超限尾段或後續行拆成另一則訊息；F2 只顯示固定無效提示。 |
| TERM-030 | 保證範圍是已啟用收集模式內的一般文字換行不提交，以及模式交接排空當下已緩衝內容。ConsoleKeyInfo 沒有實體按鍵／貼上來源標記，無法辨識含 F3 等控制序列或延遲尾段的來源；排空不等於驗證「真人新按鍵」。不以此宣稱防禦惡意終端機、輸入注入或任意控制序列貼上。 |
| TERM-031 | 未先 F3 的換行仍可能按 Enter 提交，busy 中後續內容會被丟棄；`/help` 須明示多行貼上前先進入收集。第一版不開啟／解碼 bracketed paste、不改寫終端機貼上協定、不用速度推測補救；不支援的控制輸入按無效處理，不能聲稱所有直接貼上都會自動安全合併。 |

## 5. 完整安全草稿預覽

| 編號 | 要求 |
|---|---|
| TERM-032 | F2 只在正常且有效的編輯狀態受理。對當前原始草稿先執行當前政策的 `CanSendOrUse(..., ContentBoundary.ModelInput)`，再組合完整顯示；不得先輸出前綴／安全行再檢查後段，也不得改以遮蔽版本作合法草稿或模型輸入。 |
| TERM-033 | 預覽是一次不可變草稿快照，包含固定「草稿預覽；尚未送出」、每個邏輯行的一基行號、完整內容及一基游標行／文字元素欄。空草稿顯示一個空邏輯行；尾端 LF 形成最後空行。Tab 顯示為字面 `\t`，內容的反斜線顯示為 `\\`，區分真正 Tab 與原文 `\t`，不改待送文字。 |
| TERM-034 | 所有預覽內容採既有純文字控制字元處理，組合標籤／行號／游標及跳脫後，再對完整區塊進行當前敏感檢查與既有最終遮蔽邊界。不得輸出 ANSI／OSC、游標重畫、超連結、內部絕對路徑或原始物件。固定提示亦走相同安全輸出邊界。 |
| TERM-035 | 最大完整預覽為 65536 個嚴格 UTF-8 bytes，包含全部標籤、行號、跳脫、TERM-038 的尾端說明／編輯提示與結尾換行，全部先組合檢查再寫出。有界組合且超限整段拒絕，不先建立無上限字串、不截斷行、不分頁顯示半份草稿。拒絕不生成、不提交、不建立歷史。 |
| TERM-036 | 原始草稿含當前 Key 時清除草稿及瀏覽還原副本，結束本次草稿並以固定提示「草稿含當前 Key；已清除且未送出。」在同一次 ReadInputAsync／同一讀取者內重新開啟空白草稿；既有其他安全歷史不因此自動清除。不得回傳帶原文的 Submitted，亦不回傳 Cancelled／Unavailable 讓核心誤退出；停止訊號及 I/O 失敗仍優先。 |
| TERM-037 | 若原始草稿安全，但完整顯示區塊因拼接／跳脫後敏感碰撞、容量或編碼而不能安全呈現，只輸出「無法完整安全預覽；草稿尚未送出。」並保留隱藏草稿；終端機 I/O 失敗則依第 10 節停止。預覽超限不調高草稿或模型限制，後續送出仍重新檢查。 |
| TERM-038 | 預覽輸出後附固定「以上為預覽當時的草稿；繼續編輯不會更新此預覽。」及編輯提示，再排空輸出期間已緩衝的普通輸入，然後繼續同一個讀取者。取消／EOF 優先處理；預覽期間的 Enter 不得成為提交。草稿、游標及瀏覽位置保持，預覽不取得操作核准。 |
| TERM-039 | 預覽不自動發生於每次輸入、歷史回取、貼上結束或工具完成。一般訊息送出時重新檢查目前草稿，不以舊預覽作敏感通行證；單行本機指令依 TERM-050 的既有路由，F2 的敏感檢查則一律沒有命令例外。既有終端機捲動內容不會被清除或自動更新，不宣稱秘密已從終端機／runtime 所有複本抹除。 |

## 6. 記憶體內輸入歷史

| 編號 | 要求 |
|---|---|
| TERM-040 | 只收錄正式提交後通過一般訊息准入的完整原始文字；包含多行，但不含本機命令、未知命令、Key／換 Key 選單、三種核准答案、空白、Invalid、敏感拒絕或規則准入失敗輸入。生成預算、模型或工具在收錄後失敗仍可回取；若觸發共同安全重設，依第 10 節清除。 |

| TERM-043 | 歷史項不可變，編輯回取內容不覆寫歷史。瀏覽期間的編輯只修改當前工作副本，繼續 Ctrl＋P／N 時丟棄該副本改載原歷史；Ctrl＋N 越過最新仍還原初次瀏覽前的草稿。欲保留編輯結果可直接提交；提交、Ctrl＋U 或清除結束瀏覽並釋放還原副本，Ctrl＋U 留空草稿。 |
| TERM-044 | 每次候選收錄、回取、預覽及一般訊息正式送出重新執行當前敏感檢查；不以歷史曾接受作豁免。回取候選若不安全，清除全部歷史與還原副本、保留回取前安全草稿並結束瀏覽，只顯示固定拒絕提示；若該草稿也不安全則一併清除。不逐筆跳過並自動載入另一項。 |
| TERM-045 | 回取不顯示原文、星號、歷史序號、長度或摘要；只在明確 F2 時安全預覽，或正式提交通過准入後沿既有流程顯示。沒有歷史時 Ctrl＋P／N 無動作，不自動建立空項或讀檔。 |
| TERM-046 | 草稿與歷史屬 CLI 操作資料，不加入模型歷史、摘要來源、pins、PlanStore、Git 帳本、工具結果或完成證據。模型只取得使用者正式送出且通過准入的那一筆；回取不自動恢復舊工具結果、來源版本或核准。 |
| TERM-047 | `/clear`、共同安全重設、開始換 Key、政策切換、釋放及退出清除所有歷史／還原副本／草稿。一般回合完成、普通取消或非重設失敗保留安全歷史；模式切換、規則 Scope 切換／重載保留安全歷史，但再次提交須按當前政策／Scope 重驗。 |
| TERM-048 | 不讀寫 shell 歷史、終端機錄製、歷史檔、環境變數、OS 秘密儲存或跨程序資料。沒有匯出、搜尋、磁碟保存或歷史載入指令；清除只釋放自有參考，不刪檔、不清終端機捲動、不保證 runtime 字串所有複本覆寫。 |

## 7. 指令相容性與提交順序

正式提交先驗證長度／編碼並處理空白，再執行單行指令閘門及既有命令路由。單行本機指令保留各自原有的敏感檢查時點及已知命令例外，不增加通用的路由前 Key 子字串拒絕。一般訊息在命令路由之後，先經當前敏感政策與目前規則准入，才通知歷史收錄、顯示使用者訊息並啟動原 Runner。F2 預覽與回取不走命令路由，其敏感檢查沒有本機命令例外。

| 編號 | 要求 |
|---|---|
| TERM-049 | 單行指令閘門必須在任何規則、Context、Review、模式或其他本機命令解析器之前。原始草稿含 LF 且 `TrimStart()` 後以 `/` 開頭即整筆拒絕，包括最後只有一個 LF；不先 Trim 掉換行、不拆行、不將餘文送模型。固定提示「本機指令只接受單行；本次未執行。」 |
| TERM-050 | 單行指令沿既有大小寫、完整匹配、參數、各路由敏感檢查及字面餘文規則；保留 CLI-AC-003 的短 Key 與已知本機指令重疊例外，例如合成 Key 為 `e` 時，直接提交 `/clear`／`/exit` 仍可執行，零原文回顯／歷史／模型。此例外不適用 F2，亦不取消 `/rules`、`/context`、`/review` 等原有路由檢查。`/rules scope DIR` 的 DIR 及 `/context pin TEXT` 的 TEXT 保留既有首尾空白，不額外解引號、展開變數或正規化。多行 pin／Scope 路徑仍不支援。 |
| TERM-051 | 一般訊息只有後續行出現 `/exit`、`/rules reload`、`/review` 或 yes，皆保留為普通文字，不執行本機指令或核准；首行以 `/` 起頭的程式碼亦受 TERM-049，不新增斜線跳脫語法。所有命令及拒絕輸入均不加入輸入歷史。 |
| TERM-052 | 貼上結束、F2、歷史回取、模式切換及進度顯示均不是提交；只有正常編輯狀態的後續 Enter 才交出 Submitted。多行一般訊息作為同一則使用者訊息，不能產生多回合或提前執行其中的指令。 |
| TERM-053 | 本份不改 `/compact`、`/review` 等明確命令原有的生成與額度語意，也不因歷史回取重送失敗需求。命令路由、規則閘門、模型實際 body 大小檢查及當前回合預算繼續生效。 |
