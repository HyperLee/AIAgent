## 3. 來源、規則鏈與操作邊界

| 編號 | 來源與範圍要求 |
|---|---|
| RULE-011 | 初始 Scope 為 `.`。只探查固定工作區根及選定 DIR 各級祖先中的 `AGENTS.md`，按根到葉順序載入；根規則適用整個工作區，較深規則只適用其目錄子樹。缺檔為合法缺席，空檔為合法來源且占一份，不掃描整個工作區尋找規則。 |
| RULE-012 | 不探查工作區外祖先、使用者家目錄、環境變數、遠端或其他檔名；`.agents`、`.codex` 及其他敏感路徑不設例外。固定候選檔名仍沿用目前檔案系統的名稱解析與安全重驗，不新增大小寫／Unicode 別名搜尋。 |
| RULE-013 | DIR 必須是工作區相對的既有安全目錄，根使用 `.`；沿用路徑正規化、合法 Unicode、4096 UTF-16 單位、拒絕 `..`／絕對路徑／連結等限制。不展開 `~`、變數或 shell 引號。規則鏈深度自根為 0 計算，最多 32；操作所需祖先超深也拒絕，不能只檢查前 32 層。 |
| RULE-014 | 記錄根到 Scope 每個候選位置的存在或缺席，包含空檔、檔案身分與穩定讀取觀察。目標操作另檢查 Scope 到目標目錄的候選位置；缺席不能永久快取，避免之後新建 `AGENTS.md` 繞過規則邊界。 |
| RULE-015 | 載入鏈保留所有祖先原文及來源，不把多份文字預先合併成模型摘要。較深來源只覆蓋同一適用範圍中的衝突開發慣例；不使祖先不衝突要求消失，不放寬程式政策。 |
| RULE-016 | 檔案工具的目標須位於目前 Scope 或其子樹；目錄工具檢查目標目錄，檔案工具檢查其父目錄規則鏈。目標在 Scope 外，或途中存在未載入的更深 `AGENTS.md`，回 `rules_scope_mismatch`，不自動讀其內容、不切 Scope；提示使用者先選該目錄。即使該規則空白，仍是待明確選擇的來源邊界。 |
| RULE-017 | `search_files`／`search_text` 每次進入目錄前探查該目錄的規則候選；遇未載入邊界整次拒絕，丟棄累積結果，不回傳部分成功。原搜尋忽略／深度／工作量上限維持；未進入的忽略子樹不另探查。`list_files` 僅檢查目標鏈，不探查直接子目錄內部；不得由其成功宣稱子目錄規則已載入。 |
| RULE-018 | `run_dotnet_task` 對直接指定 `.csproj` 的路徑套用 Scope／祖先規則檢查，仍使用既有工作區根 cwd、固定 recipe、原生隔離與逐次核准。規則中的建置方式只是文字，不能增加 argv、restore、網路或測試能力；不承諾解析整個建置輸入圖或自動載入所有間接輸入的規則。 |
| RULE-019 | Markdown／純文字內容原樣承載；不解析成可執行政策，不執行程式碼區塊，不展開連結、include、其他 AGENTS、Skills 或網頁。檔案中聲稱使用者已同意、要求換工作區或授予工具權限的文字均不產生授權。 |

例如 Scope=`src/App` 時，規則鏈可為根 `AGENTS.md`、`src/AGENTS.md`、`src/App/AGENTS.md`。讀取 `src/App/Program.cs` 可按該鏈檢查；讀取 `tests/AppTests.cs` 拒絕。若 `src/App/Feature/AGENTS.md` 存在，進入 Feature 前須先由使用者切換 Scope。切換只處理後續工作，不重播被拒絕的工具。

## 5. 內部契約、所有權與安全讀取

以下為後續最小 internal 契約，不是本次產品 API。含文字、路徑或集合的資料採密封類別、唯讀屬性、防禦性複製及固定型別標記 `ToString()`，不用一般物件序列化匯出。

| 型別／元件 | 必要資料與責任 |
|---|---|
| ProjectRulesStatus | `Unavailable`：從未取得或不能使用安全快照；`Valid`：目前可用；`Stale`：已知來源變動或規則修改後待明確重載。非 Valid 不能作模型輸入。 |
| ProjectRuleSource | 固定 Kind=`project_rule`、工作區相對 Path、來源 Scope、RawByteCount、Sha256、Text；內部另外保留穩定身分／觀察，不投影底層完整路徑。 |
| ProjectRulesSnapshot | RulesRevision、Scope、根到葉的 Sources、完整候選位置觀察（含缺席）、預先驗證的完整投影。快照不可變；有效狀態與生命週期另由 Coordinator 管理。 |
| ProjectRulesCoordinator | `Capture`、`TryChangeScopeAsync`、`TryReloadAsync`、`ValidateAsync`、`BuildAppendix`、`MarkStale`、`BindPolicy`、`DisposeAsync`；持有當前狀態及快照，協調原子決策，不直接生成或核准操作。 |
| 規則候選／操作戳記 | 捕捉 SessionGeneration、RulesGeneration、RulesRevision、Scope 及候選來源觀察；發布時比較目前身分／代次／取消。RulesGeneration 用於撤銷在途候選，RulesRevision 用於識別成功載入內容，不是授權憑證。 |

| 編號 | 契約要求 |
|---|---|
